# r2parquet 0.2.0

First release, moved from `mountainmathHelpers`.

* Reading: `parquet_tbl()` gives lazy DuckDB tables on public URLs, presigned URLs and local files without credentials, and on private R2 buckets as `r2://bucket/path`. The tables live on one connection shared for the session, `parquet_connection()`, so they can be joined with each other and with data copied there, or on a connection of your own passed as `con`. The arrow and polars readers of `mountainmathHelpers` were not carried over, neither handles GeoParquet 2.0 geometry, and uploads and listings use signed S3 requests instead of arrow, so the package has no optional dependencies.
* Spatial queries: `filter_spatial()` works on any lazy DuckDB table and only downloads the row groups that intersect the query, `collect_parquet()` collects as sf if the table has geometry.
* Writing: `data_to_parquet()` writes data frames, sf objects and lazy DuckDB tables to parquet, optionally sorted (`sort_by`) and hive partitioned (`partition_by`). sf objects and tables with GEOMETRY columns become GeoParquet 2.0 files sorted along a Hilbert curve. Given an `r2://bucket/path` destination it writes and uploads in one go, removing earlier uploads at the same path so no stale partitions remain. It returns the path, ready for `parquet_tbl()`, with the files written in the `files` attribute. `remove_stale = FALSE` keeps partitions of earlier writes, and `compression` picks the codec, zstd by default.
* Metadata: `data_to_parquet(metadata = list(source = ..., license = ..., columns = ...))` writes source, license, notes and column labels into the parquet footer, `parquet_metadata()` reads them back from paths, lazy tables or collected data, and `collect_parquet()` attaches them to the collected data as attributes, column labels as `label` attributes.
* Local cache: `parquet_tbl(cache = TRUE)` reads local copies of remote files for data that gets queried regularly, from the directory in `R2PARQUET_CACHE_PATH` or the user cache directory. Once cached, `parquet_tbl()` reads the copy by default as long as it is current, checking each copy once per session (`clear_cache_checks()` forgets the checks), and `cache = "offline"` reads it without checking. `cache_parquet()` does the syncing: it mirrors `r2://` paths and URLs into the cache, compares etags so only new and changed files get downloaded, removes files that are gone remotely, checks downloads against their MD5 etag, and falls back to the cached copy with a warning when the remote can't be reached. `list_cache()` lists the copies in the cache by the remote paths they stand for, `remove_from_cache()` removes them, and `list_parquet()` reports in its `cache` column whether a file has a current copy in the cache, a stale one or none.
* Manifests: `upload_parquet()` and partitioned `data_to_parquet()` writes to R2 put a `_manifest.json` next to the data listing the parquet files with size, etag and modification time, so that directories can be cached from public URLs, where listing is not possible, and the metadata from the files' footers, shared entries at the dataset level and the rest per file, so clients can read descriptions and column labels without opening the files (the format is documented in `?write_manifest`). `write_manifest()` adds manifests to existing directories, reading the footers on R2, `remove_parquet()` removes them with directories, and uploads and removals keep the manifests of the directories above the changed files current, so adding or removing a file or partition of a dataset updates the dataset's manifest.
* Managing R2: `create_r2_bucket()` creates private or public buckets, `upload_parquet()` and `remove_parquet()` upload and delete files and purge them from the Cloudflare cache of the bucket's custom domains. `upload_parquet(remove_stale = TRUE)` removes the parquet files below the destination that are no longer in the uploaded directory, so a rebuilt dataset gets mirrored (off by default, unlike for `data_to_parquet()`, which only removes its own partitions). Single files of any type that go with a dataset, like a JSON index, go up with the content type for their extension, and `remove_parquet()` removes them by path. `remove_parquet()` takes several paths at once and resolves all of them before removing anything. `list_parquet()` lists the parquet files at R2 paths, URLs (files via their headers, directories via their manifest) or local paths, or the files a lazy table reads, with file name, size, modification time, cache status, etag and path.
* Sharing private files: `presigned_url()` creates time limited download (or upload) URLs for one or more files.
* Files on R2 are given as `r2://bucket/path` throughout, for reading, writing, uploading, removing and presigning.
