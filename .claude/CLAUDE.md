# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`r2parquet` publishes parquet and GeoParquet files on Cloudflare R2 and reads them lazily. It was split out of `mountainmathHelpers` (October 2026), which no longer carries wrappers for these functions. Installed from GitHub (`mountainMath/r2parquet`), not on CRAN.

## Commands

```sh
Rscript -e 'devtools::document()'   # regenerate NAMESPACE and man/*.Rd from roxygen comments
Rscript -e 'devtools::test()'       # testthat suite
Rscript -e 'rcmdcheck::rcmdcheck(args = c("--no-manual", "--as-cran"), error_on = "warning")'  # what CI runs
```

- `NAMESPACE` and `man/` are roxygen-generated, never edit them by hand.
- Vignettes are precomputed: edit the sources in `vignettes.orig/` (`.Rbuildignore`'d), then `Rscript vignettes.orig/precompute.R [name ...]` knits them with live data (and R2 credentials where needed) into `vignettes/`, figures included. Never edit `vignettes/*.Rmd` directly. The pkgdown action (`.github/workflows/pkgdown.yaml`) only renders the precomputed files and deploys to GitHub Pages, it has no credentials.
- `test-signing.R`, `test-delete.R`, `test-upload.R`, `test-list.R`, `test-cache.R` and `test-cloudflare.R` run offline, mocking `r2_request()` (or `r2_list_objects()`, `r2_get_object()`, `http_get()`/`http_probe()`/`http_download()`) and the Cloudflare API. Most tests in `test-write.R` and all in `test-geoparquet.R` download the DuckDB `spatial`/`httpfs` extensions and are skipped on CRAN and offline. `test-r2.R` is an integration test against a real bucket, skipped unless `R2_TEST_BUCKET` and the R2 credentials below are set; it writes under a random `r2parquet-tests/` prefix and removes it again.

## Configuration

Read at call time from environment variables:

| Setting | Used by |
| --- | --- |
| `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` | `presigned_url()`, `upload_parquet()`, `remove_parquet()`, `parquet_tbl()` and `data_to_parquet()` on `r2://` paths |
| `R2PARQUET_CACHE_PATH` | `cache_parquet()`, `parquet_tbl()` (the `cache` argument), `list_cache()`, `remove_from_cache()` and the `cache` column of `list_parquet()`, the cache directory; falls back to `tools::R_user_dir("r2parquet", "cache")`. It is the only way to choose the directory, a path argument was dropped before the first release since the cache functions all work on the one configured directory |
| `R2_ACCOUNT_ID`, `R2_API_TOKEN` | `create_r2_bucket()` (Cloudflare REST API via `httr`; bucket settings like public access are not available through R2's S3-compatible API). With `custom_domain` it looks up the domain's zone via `/zones`, so the token also needs Zone Read on that zone, and the zone has to be active in the same account. `upload_parquet()` and `remove_parquet()` also use this token (if set) to purge changed files from the Cloudflare cache of the bucket's custom domains (`r2_purge_cache()`, needs Zone Cache Purge); a failed purge only warns since the objects have already changed |

## Architecture

**R2 access (`R/r2.R`).** Everything goes through the S3-compatible API via `r2_request()`, signed by the package's own SigV4 implementation (`sigv4_headers()`, `sigv4_presigned_url()`; `test-signing.R` checks them against AWS's published examples); neither arrow nor `aws.s3` are used (arrow was a heavy dependency, `aws.s3` cannot address R2 when `AWS_DEFAULT_REGION` is set). Uploads are single `PUT` requests per file (`r2_put_object()`), with the file read into memory so the payload hash can be signed; `httr::upload_file()` streaming was tried and dropped because httr only closes the file connection on a short read, which leaks connections. The 5 GB single-PUT limit applies, there is no multipart upload. Listings use `ListObjectsV2` (`r2_list_objects()`, paginated, parsed with the regex helpers `xml_elements()`/`xml_field()` since the responses are flat); `r2_objects()` narrows a listing to the object at a path plus the objects below it as a directory, excluding keys that merely share the prefix like `path.bak`, and is how `remove_parquet()`, `list_parquet()` and the stale-partition cleanup tell files, directories and missing paths apart. Deletes use the batch `POST ?delete` API (1000 keys per request, needs a `Content-MD5` header). `presigned_url()` signs locally with `X-Amz-Expires` capped at 7 days, as for S3. All functions address files on R2 as `r2://bucket/path` (`r2_split_path()`), the functions return uploaded/removed files in that form too. Directories of parquet files are often themselves named `*.parquet`, so `r2_parquet_glob()` (used by `parquet_tbl()`) sends a signed `HEAD` request for such paths to tell a file from a directory.

**Writing (`R/write.R`).** `data_to_parquet()` writes data frames, sf objects and lazy DuckDB tables (the latter via `COPY` on the table's own connection, without collecting) with a single DuckDB `COPY`, rows ordered by `sort_by`, optionally hive partitioned by `partition_by`. sf objects, and lazy tables with GEOMETRY columns, become GeoParquet 2.0 (native parquet `GEOMETRY` type with the crs in the column type and a bounding box per row group) via `GEOPARQUET_VERSION 'V2'`; for sf the geometry column is always named `geometry` and invalid geometries are fixed with `sf::st_make_valid()`, casting back to the original multi type so geometry types stay consistent (StatCan boundary files contain invalid geometries). Spatial rows are sorted by `ST_Hilbert` over the data's extent (after `sort_by`) so the row group bounding boxes are selective. No separate `bbox` covering column is written (removed before the first release): DuckDB prunes on the native geometry statistics, and without GeoParquet `covering` metadata other tools wouldn't use it either. Partitioned writes run with `SET threads = 1` because multi-threaded `PARTITION_BY` writes interleave chunks within partition files (DuckDB 1.5.6), and stale partitions are removed first (`remove_stale = TRUE`) since DuckDB's `OVERWRITE` keeps them. Partition columns are only in the directory names (DuckDB's default; they come back as strings, `"001"` stays `"001"`). For `r2://` destinations `data_to_parquet()` (`r2_data_to_parquet()`) writes to a temp dir via `local_data_to_parquet()` and uploads via `upload_parquet()`, removing stale partitions at the destination first with `remove_stale = TRUE`. `list_parquet()` lists files locally (`dir()`) or on R2 (`r2_parquet_files()` on `r2_objects()`), and for a lazy table strips the `**/*.parquet` glob `parquet_tbl()` stored in `r2parquet_paths` back to the directory.

**GeoParquet reading (`R/geoparquet.R`).** `filter_spatial()` works on any lazy DuckDB table and always emits a `geom && envelope` condition before `ST_Intersects`: as of DuckDB 1.5.6 only `&&`/`ST_Intersects_Extent` prune row groups via the geometry statistics, a plain `ST_Intersects` downloads all geometry. `collect_parquet()` collects any lazy DuckDB table, turning GEOMETRY columns (WKB raw lists) into sf with the crs from the column type via `DESCRIBE`, and attaches the file metadata.

**Metadata (`R/metadata.R`).** `data_to_parquet(metadata=)` writes a named list into the parquet footer via DuckDB's `KV_METADATA` copy option, single values as strings and everything else (notably `columns`, the per-column labels/descriptions, which also picks up `label` attributes of data frame columns) as JSON; `geo` is reserved for GeoParquet. `parquet_metadata()` reads it back with `parquet_kv_metadata()`, parsing JSON values and dropping `geo`, from paths or from a lazy table. `parquet_tbl()` stores the resolved paths as the `r2parquet_paths` attribute of the lazy table, which dbplyr (2.6) keeps through all verbs on the left-hand table, so `collect_parquet()` can look up the metadata at collect time and attach it as the `metadata` attribute plus `label` attributes on columns. Footer metadata can only be changed by writing the data again.

**Reading (`R/parquet.R`).** `parquet_tbl()` is the one reader, for public URLs (like a public bucket's custom domain or presigned URLs), private R2 files as `r2://bucket/path` and local paths. It returns a lazy `dbplyr` table on a single session-cached in-memory DuckDB connection, exported as `parquet_connection()`, so all tables can be joined; `con=` puts the table on a user's own connection instead. Arrow and polars readers (an `engine` argument) existed before the first release and were dropped: arrow reads GeoParquet 2.0 geometry as plain binary without crs, polars (1.16) rejects the native GEOMETRY type outright, and neither is on the DuckDB connection, so `filter_spatial()`/`collect_parquet()` didn't apply; polars also isn't on CRAN. Adding an `engine` argument back later is backward compatible. For `r2://` paths `parquet_tbl()` runs `CREATE OR REPLACE SECRET` on every call, so credentials are only needed once R2 is read and changed credentials get picked up; the secret sets `REGION 'auto'` explicitly, otherwise DuckDB takes the region from `AWS_DEFAULT_REGION` and R2 rejects it. The R duckdb package sets `autoinstall_known_extensions = false`, so extensions have to be `INSTALL`ed explicitly even though they autoload afterwards: `httpfs` gets installed for URLs, and `spatial` only when `DESCRIBE` (footer only) shows a GEOMETRY column, since spatial functions like `ST_MakeEnvelope`/`&&` do not autoload. GEOMETRY columns and `ST_CRS` work without `spatial` (the crs then comes back as PROJJSON instead of `EPSG:n`).

**Local cache and manifests (`R/cache.R`).** `cache_parquet()` mirrors remote datasets into a cache directory, `r2://bucket/path` as `r2/<account id>/bucket/path` (bucket names are only unique per account) and URLs as `<scheme>/<host>/<path>` without the query string, and `parquet_tbl(cache=)` reads the local copy, so everything downstream sees plain local paths. `cache = NULL` (the default) goes through `cache_lookup()`: a path without a copy in the cache (`cached_copy()`) is read remotely without any request, a copy is checked against the remote (`cache_current()`, every remote file current by etag and size and no extra local parquet files in a directory) and used if current, otherwise the remote path is read with a warning and the copy is left alone; `cache = TRUE` goes through `cache_parquet()` and updates the copy; `cache = "offline"` (`cache_offline()`) returns the copy without any request, stale or not, and errors without one, for offline work and for comparing the copy with the remote (`cache = FALSE`). Freshness is per file by etag: for `r2://` from the listing (`r2_list_objects()` parses `ETag`, which R2 sets to the content MD5 for single-PUT uploads, so downloads get verified against it when it looks like an MD5), for file URLs from a GET of the first byte (`http_probe()`, `Range: bytes=0-0`; a `HEAD` gets 403 on presigned URLs since they are signed for GET, the 206 response carries the etag and the total size in `Content-Range`), and for directory URLs from a `_manifest.json` next to the data, since directories can't be listed over https. One manifest per directory, JSON with `directory` (whether it lists everything below, as R2 manifests and cached directories do, versus only cached single files) and `files` with path, size, etag and modified; the `directory` flag is what the offline fallback (`cached_copy()`) checks so a directory holding a cached single file isn't mistaken for a cached dataset. Local manifests must stay sidecars, the etag is a hash of the file. On R2, `r2_upload()` (behind `upload_parquet()` and `r2_data_to_parquet()`) creates the manifest for directory uploads and updates an existing one for single files via `r2_update_manifest()`, `remove_parquet()` deletes manifests below removed directories and rewrites them after single-file removals, `write_manifest()` adds them to existing directories, and all of them purge the manifest from the Cloudflare cache along with the data. Downloads go through `r2_get_object()` (`r2_request(config=httr::write_disk())`, streaming, unlike uploads) to a `.download` temp file that is renamed into place. `list_cache()` and `remove_from_cache()` work on the configured cache directory like everything else: `cache_contents()` reads every local manifest and maps the local paths back to remote ones with `cache_remote_path()`, the reverse of `cache_location()` (`cache_directory()` returns forward slashes so these paths compare with what `dirname()`/`dir()` return on Windows; tests use `local_cache_dir()` from `helper.R` for the same reason), and `remove_from_cache()` deletes the copy and then `prune_manifests()` walks up to the cache directory dropping the entries from ancestor manifests, flipping a directory manifest to `directory=FALSE` when it loses entries (so the offline fallback no longer treats it as complete) and removing emptied directories. `list_parquet()` gets its `cache` column from `cache_status()`, comparing the remote etag with the one the manifest recorded (`NA` when either is unknown, e.g. local paths); for URLs `list_parquet()` lists through `url_cache_source()` as well, so files get size and etag from their headers and directories are listed from their manifest, falling back to a bare row with `NA`s.

**Why not duckdbfs.** `duckdbfs` covers similar reading ground, but the CRAN version lacks crs reading for GeoParquet and the package does not seem actively maintained, so the thin DuckDB readers here are kept on purpose.

**Dependencies.** Everything is called with explicit `pkg::fn()` qualification, there are no namespace imports. `duckdb`, `DBI`, `dbplyr`, `dplyr`, `sf`, `httr`, `digest` and `jsonlite` are the hard dependencies, there are no optional ones (`Suggests` only holds test and vignette tooling).
