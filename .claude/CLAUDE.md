# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`r2parquet` publishes parquet and GeoParquet files on Cloudflare R2 and reads them lazily. It was split out of `mountainmathHelpers` (October 2026), which no longer carries wrappers for these functions. Installed from GitHub (`mountainMath/r2parquet`), not on CRAN.

## Commands

```sh
Rscript -e 'devtools::document()'   # regenerate NAMESPACE and man/*.Rd from roxygen comments
Rscript -e 'devtools::test()'       # testthat suite
Rscript -e 'rcmdcheck::rcmdcheck(args = c("--no-manual", "--as-cran"), error_on = "warning")'  # what CI runs
```

- `NAMESPACE` and `man/` are roxygen-generated, never edit them by hand.
- Vignettes are precomputed: edit the sources in `vignettes.orig/` (`.Rbuildignore`'d), then `Rscript vignettes.orig/precompute.R [name ...]` knits them with live data (and R2 credentials where needed) into `vignettes/`, figures included, all in one R session, resetting the package's once-per-session messages (`parquet_cache$*_noted`) before each vignette so their output doesn't depend on which others were knitted before. Never edit `vignettes/*.Rmd` directly. The pkgdown action (`.github/workflows/pkgdown.yaml`) only renders the precomputed files and deploys to GitHub Pages, it has no credentials. `uploading_data.Rmd` needs the StatCan downloads in `~/Downloads` and uploads to `r2://test/census/2021/`; `metadata.Rmd` only reads the public bucket at `https://data.mountainmath.ca/census/2021/` and needs no credentials (its `_manifest.json` was written with `write_manifest()` on 2026-10-13 and is patched by the uploads below it; the partitioned example is the `profile_ADA/` census profile dataset, the `dot-wasm/` manifests in that bucket predate the metadata and are left alone); `uploading_data.Rmd` removes its uploads again.
- `test-signing.R`, `test-delete.R`, `test-upload.R`, `test-list.R`, `test-cache.R`, `test-metadata.R`, `test-parquet.R`, `test-credentials.R` and `test-cloudflare.R` run offline, mocking `r2_request()` (or `r2_list_objects()`, `r2_get_object()`, `http_get()`/`http_probe()`/`http_download()`) and the Cloudflare API; the directory-URL test in `test-parquet.R` serves a temp directory with `python3 -m http.server` (`local_http_server()`, skipped on Windows and without python3). Most tests in `test-write.R` and all in `test-geoparquet.R` download the DuckDB `spatial`/`httpfs` extensions and are skipped on CRAN and offline. `test-r2.R` is an integration test against a real bucket, skipped unless `R2_TEST_BUCKET` and the R2 credentials below are set; it writes under a random `r2parquet-tests/` prefix and removes it again.

| --- | --- |

| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`, `AWS_REGION`/`AWS_DEFAULT_REGION` (default `us-east-1`), `AWS_ENDPOINT_URL_S3`/`AWS_ENDPOINT_URL`, `R2PARQUET_S3_URL_STYLE` | everything on `s3://` paths (`s3_settings()`, `bucket_store()` in `R/r2.R`): Amazon S3, or other S3 compatible services via the endpoint; vhost style URLs on AWS (path style for dotted bucket names), path style with a custom endpoint, the variable overrides. AWS profiles are not read |
| `R2PARQUET_CACHE_PATH` | `cache_parquet()`, `parquet_tbl()` (the `cache` argument), `list_parquet_cache()`, `remove_parquet_from_cache()` and the `cache` column of `list_parquet()`, the cache directory; falls back to `tools::R_user_dir("r2parquet", "cache")`. It is the only way to choose the directory, a path argument was dropped before the first release since the cache functions all work on the one configured directory |
| `R2_ACCOUNT_ID`, `R2_API_TOKEN` | `create_r2_bucket()` (Cloudflare REST API via `httr`; bucket settings like public access are not available through R2's S3-compatible API). With `custom_domain` it looks up the domain's zone via `/zones`, so the token also needs Zone Read on that zone, and the zone has to be active in the same account. `upload_parquet()` and `remove_parquet()` also use this token (if set) to purge changed files from the Cloudflare cache of the bucket's custom domains (`r2_purge_cache()`, needs Zone Cache Purge); a failed purge only warns since the objects have already changed |
| `R2PARQUET_PURGE_ORIGINS` | `r2_purge_cache()`: comma or whitespace separated origins (`purge_origins()`, trailing slashes dropped); each URL is purged plain and once per origin with an `Origin` header, since Cloudflare caches responses to requests with an `Origin` header (browsers, `vary: Origin`) separately per origin and a plain purge leaves them stale (checked on data.mountainmath.ca 2026-10-21). The variable rather than an argument because the origins belong to the deployment; origins not listed stay stale until the edge TTL runs out |

## Architecture

**R2 access (`R/r2.R`).** Everything goes through the S3-compatible API via `r2_request()`, signed by the package's own SigV4 implementation (`sigv4_headers()`, `sigv4_presigned_url()`; `test-signing.R` checks them against AWS's published examples); neither arrow nor `aws.s3` are used (arrow was a heavy dependency, `aws.s3` cannot address R2 when `AWS_DEFAULT_REGION` is set). Uploads are single `PUT` requests per file (`r2_put_object()`), with the file read into memory so the payload hash can be signed; `httr::upload_file()` streaming was tried and dropped because httr only closes the file connection on a short read, which leaks connections. The 5 GB single-PUT limit applies, there is no multipart upload. `upload_parquet()` (`r2_upload()`) takes directories of parquet files and single files of any type (a JSON index next to a dataset, say), the content type comes from the extension via `r2_content_type()` (`mime::guess_type()`, parquet stays `application/octet-stream`); it refuses `_manifest.json` since manifests are generated, and keys containing `*`, `?` or `[`, which DuckDB reads as glob patterns when such a file is queried (refusing at upload time was chosen over escaping in the readers). `remove_parquet()` removes directories' parquet files and manifests, and a file path of any type (listed via `r2_objects()`, so no `HEAD` is needed); it also takes local paths (`local_removal()`: the same directory rule plus emptied directories, single files only if they start with the parquet magic bytes (`is_parquet_file()`, a guard against accidents, `unlink()` removes others), refusing paths in the cache directory, whose manifests `remove_parquet_from_cache()` keeps in line; local writes create no manifests, so none above get patched) and lazy tables (`table_source()`, shared with `list_parquet()`), and refuses URLs; separate `upload_file()`/`remove_file()` exports existed briefly in October 2026 and were folded back in to keep the API small. `upload_parquet(remove_stale=TRUE)` (in `r2_upload()`) deletes every parquet file below the destination directory that is not in the upload, mirror semantics, which is why it defaults to `FALSE`, while `data_to_parquet()`'s `remove_stale` (default `TRUE`) only removes hive partition files. Listings use `ListObjectsV2` (`r2_list_objects()`, paginated, parsed with the regex helpers `xml_elements()`/`xml_field()` since the responses are flat); `r2_objects()` narrows a listing to the object at a path plus the objects below it as a directory, excluding keys that merely share the prefix like `path.bak`, and is how `remove_parquet()`, `list_parquet()` and the stale-partition cleanup tell files, directories and missing paths apart. Deletes use the batch `POST ?delete` API (1000 keys per request, needs a `Content-MD5` header). `presigned_url()` signs locally with `X-Amz-Expires` capped at 7 days, as for S3. All functions address files on R2 as `r2://bucket/path` (`r2_split_path()`, which strips leading and trailing slashes and returns `directory=TRUE` when the path ended in a slash, the one place that meaning is kept: `r2_upload(directory=)` puts a single file into the directory, `r2_parquet_glob(is_directory=)` skips the `HEAD`, `presigned_url()` refuses it), the functions return uploaded/removed files in that form too. `r2_dataset_objects()` narrows a listing to the file at a path or the parquet files below it, for `r2_parquet_files()` (`list_parquet()`) and `r2_cache_source()` alike. Directories of parquet files are often themselves named `*.parquet`, so `r2_parquet_glob()` (used by `parquet_tbl()`) sends a signed `HEAD` request for such paths to tell a file from a directory.

**S3 (`R/s3.R`, `R/r2.R`).** `s3://bucket/path` goes through the same code as `r2://`: internally an R2 bucket is its name and an S3 bucket the string `"s3://name"`, `bucket_store()` turns either into endpoint, region, credentials and URL style for `r2_request()`, `bucket_url()` builds paths back, `bucket_label()` names the bucket in messages, `is_bucket_path()` tests for either scheme, and `duckdb_bucket_secrets()` creates the DuckDB secret for the schemes a read needs. Session tokens are signed as `x-amz-security-token`; the Cloudflare purge is skipped for S3; the cache keeps S3 copies under `s3/aws/` or `s3/<host>_<port>/` for custom endpoints; downloads skip the MD5 check when the response says the object is KMS or customer-key encrypted (`etag_is_md5()`). `xml_unescape()` decodes numeric character references because MinIO returns etags as `&#34;…&#34;`. Public access on S3 is a bucket policy statement granting `s3:GetObject` on `prefix/*` (`set_s3_public_access()`, Sid `r2parquetPublicRead` plus a hash of the resource, other statements kept, the policy deleted when empty, Block Public Access checked first); per-object ACLs were rejected since they are disabled on new buckets. Amazon S3 propagates policy changes with a delay: for a few minutes anonymous GETs intermittently get 403 while HEADs already succeed, so the integration test (`wait_until_public()` in `helper.R`) and the `s3` vignette probe with ranged GETs. `test-s3.R` mocks the policy calls; `test-r2.R` runs the round trip on S3 too when `S3_TEST_BUCKET` (bucket, optionally with a path) and the AWS credentials are set, and with `AWS_ENDPOINT_URL` against MinIO. The `s3` vignette writes to `s3://mountainmath/test/vignette` and removes everything and the public access again.

**Writing (`R/write.R`).** `data_to_parquet()` writes data frames, sf objects and lazy DuckDB tables (the latter via `COPY` on the table's own connection, without collecting) with a single DuckDB `COPY`, rows ordered by `sort_by`, optionally hive partitioned by `partition_by`. sf objects, and lazy tables with GEOMETRY columns, become GeoParquet 2.0 (native parquet `GEOMETRY` type with the crs in the column type and a bounding box per row group) via `GEOPARQUET_VERSION 'V2'`; for sf the geometry column is always named `geometry` and invalid geometries are fixed with `sf::st_make_valid()`, casting back to the original multi type so geometry types stay consistent (StatCan boundary files contain invalid geometries); repairs get recorded in the metadata (`record_geometry_repairs()` in `R/geoparquet.R`): `processing` with the count over the whole data (so partition files share it) and the GEOS or s2 version since `st_make_valid()` results depend on it, and `geometry_repairs` listing the repaired rows (up to 1000) by the declared `primary_key` or else by `id_column()`, the first column or one ending in `ID` that is unique (a guessed column is never written as `primary_key`), with a warning and just the count otherwise; entries given in `metadata` are kept. A `primary_key` metadata entry (one or more columns, written as a JSON array, following Frictionless Table Schema's `primaryKey`) is checked by `check_primary_key()` in SQL on the write source, for existence, missing values and uniqueness, before writing; there is deliberately no warning for writes without one. Spatial rows are sorted by `ST_Hilbert` over the data's extent (after `sort_by`) so the row group bounding boxes are selective. No separate `bbox` covering column is written (removed before the first release): DuckDB prunes on the native geometry statistics, and without GeoParquet `covering` metadata other tools wouldn't use it either. Partitioned writes run with `SET threads = 1` because multi-threaded `PARTITION_BY` writes interleave chunks within partition files (DuckDB 1.5.6). They `COPY` into a hidden temp directory next to `path` and `move_partitions()` then removes stale partitions (`remove_stale = TRUE`, since DuckDB's `OVERWRITE` keeps them) and renames the new files into place: removing stale partitions before the `COPY` deleted the source of an in-place rewrite (`parquet_tbl(p) |> mutate(...) |> data_to_parquet(p, partition_by=)`), and a failed write now leaves the dataset alone; a file at `path` gets replaced by the directory (refused with `remove_stale = FALSE`). Single files need none of this, DuckDB writes them to a temp file and renames it. Metadata is not carried over automatically: an `inherit_metadata` argument (merging inherited entries, dropping stale primary keys, a `derived` provenance entry) existed briefly in October 2026 and was removed as too opaque, since inherited claims may not hold for changed data. Instead, with `metadata = NULL`, `warn_dropped_metadata()` warns when `source_metadata()` finds metadata in the source (a lazy table's `r2parquet_paths` via `parquet_metadata()`, so manifests for remote sources, read before the write; a data frame's `metadata` attribute), listing the entry names and pointing to `metadata = parquet_metadata(data)`, `modifyList()` and `metadata = list()`, which writes none silently; there is deliberately no warning for writes whose source has no metadata. Metadata passed with the `parquet_metadata` class (also through `[` and `modifyList()`) counts as describing the source: its `columns` entries for absent columns are dropped (a plain list errors on them, catching typos) and geometry repairs replace its `processing`/`geometry_repairs`; a `primary_key` is checked like any other and errors when it no longer holds. Partition columns are only in the directory names (DuckDB's default; they come back as strings, `"001"` stays `"001"`). For `r2://` destinations `data_to_parquet()` (`r2_data_to_parquet()`) writes to a temp dir via `local_data_to_parquet()` and uploads via `upload_parquet()`, removing stale partitions at the destination first with `remove_stale = TRUE`. `list_parquet()` lists files locally (`dir()`) or on R2 (`r2_parquet_files()` on `r2_objects()`), and for a lazy table strips the `**/*.parquet` glob `parquet_tbl()` stored in `r2parquet_paths` back to the directory.

**GeoParquet reading (`R/geoparquet.R`).** Spatial filters are the `sf::st_filter` method for lazy DuckDB tables (registered for `tbl_duckdb_connection` and `tbl_r2parquet_connection`, the two share no class below `tbl_dbi`; a `filter_spatial()` export was replaced by it in October 2026). It maps the sf predicates to DuckDB functions (`duckdb_predicates`, `dist` of `st_is_within_distance` to `ST_DWithin`, units converted to the crs units), transforms `y` to the crs of the data, ORs the predicate over the features of `y` (unioned only for intersects/within distance, where that is equivalent) and always emits a `geom && envelope` condition first (grown by `dist`, none for `st_disjoint`): as of DuckDB 1.5.6 only `&&`/`ST_Intersects_Extent` prune row groups via the geometry statistics, a plain `ST_Intersects` downloads all geometry. DuckDB is planar, so it warns for longitude/latitude data while `sf::sf_use_s2()` is on; tests on the longitude/latitude nc data turn s2 off. `collect_parquet()` collects any lazy DuckDB table, turning GEOMETRY columns (WKB raw lists) into sf with the crs from the column type via `DESCRIBE`, and attaches the file metadata.

**Metadata (`R/metadata.R`).** `data_to_parquet(metadata=)` writes a named list into the parquet footer via DuckDB's `KV_METADATA` copy option, single values as strings and everything else (notably `columns`, the per-column labels/descriptions, which also picks up `label` attributes of data frame columns) as JSON; a string that itself looks like JSON (starts with `[`, `{` or `"`) is written as a JSON string so it reads back as a string; `geo` is reserved for GeoParquet. `read_parquet_footers(con,path)` is the one footer reader (`parquet_kv_metadata()` per file, JSON values parsed, `geo` dropped): `merge_footers()` merges a set of footers, first file wins with a warning on conflicts, `duckdb_parquet_metadata()` does that for footers read on a connection (`parquet_metadata(from_files=TRUE)`), and `parquet_footers()` reads on a fresh connection for the manifests (`common_metadata()` in `R/cache.R` then splits shared from per-file entries). `parquet_metadata()` on `r2://` paths and URLs reads the manifest instead of the footers by default (`manifest_footers()`: the nearest `_manifest.json` at or above the path, found by GETting the path's own and then each ancestor's via `r2_get_manifest()`/`url_get_manifest()` (both `manifest_response()`: NULL on 404, an empty manifest without metadata with a warning when the body can't be parsed), up to the bucket or host root, where a denied GET counts as no manifest, since S3 answers 403 for missing objects without listing rights and the footer read that follows fails on its own when access to the data is denied; the entries at or below the path are merged like footers), one request for a dataset instead of a footer read per file; it falls back to the footers when no manifest covers the path, the nearest one predates the metadata (`has_metadata`), the path is a presigned URL (query string) or `from_files = TRUE`, and a lazy table (`scan_metadata()`, shared by `parquet_metadata()`, `parquet_sources()` and `collect_parquet()`) reads the manifests of the paths it was given (`r2parquet_source`) only when the files it reads (`r2parquet_paths`) are remote too and the manifests cover all paths, so cached copies read local footers. The manifest can lag files changed with other tools, which `write_manifest()` repairs. `parquet_tbl()` records the columns a table starts out with (after the language selection) in its `parquet_scans` entry (`columns`) and `collect_parquet()` messages once per session (`note_unselected_columns()`, `parquet_cache$columns_noted`) when a remote scan (`is_remote()` on the files read, so cached copies are exempt) still has all of them in the table being collected, with a `select()` of the current columns to paste in and prune, since parquet downloads only the selected columns; checked before the collect-time language swap, so the names are the ones the user's query sees, and mutate/filter still trigger it while select/summarise don't (added 2026-10-23 at Jens's request). `parquet_tbl()` stores the resolved paths as the `r2parquet_paths` attribute of the lazy table, which dbplyr (2.6) keeps through all verbs on the left-hand table, so `collect_parquet()` can look up the metadata at collect time and attach it as the `metadata` attribute plus `label` attributes on columns. Footer metadata can only be changed by writing the data again. `parquet_metadata()` returns the named list with the class `parquet_metadata` (`new_parquet_metadata()`), which only changes printing (`format.parquet_metadata()`: one line per entry cut to the console width, lists as compact JSON, `columns` as a table of labels and descriptions; entries in several languages are consolidated by `language_rows()` into one row with a cell per language under a header of the language names (`display_languages()`: the `language` entry's first, or "plain" for plain text without one, the languages are `metadata_languages()`, nothing is guessed from top-level keys; `resolve_language()` uses the same set), rows without variants span the width, and `column_row()` joins label and description per language) and keeps the class through `[`; it stays a list rather than a tibble so `$` access and passing it to `data_to_parquet(metadata=)` keep working (`local_data_to_parquet()` unclasses it). The `metadata` attribute of collected data stays a plain list, `parquet_metadata()` adds the class. dbplyr keeps attributes only for the left-hand table of joins, so `parquet_tbl()` also records each table in the session environment `parquet_scans`, keyed by the SQL of its `read_parquet()` scan (entries hold `paths`, `source`, the `key` and, once `scan_footers()` read it, `metadata`: the metadata of a table is read once per table since `select_language()`, `collect_parquet()` and `parquet_sources()` all need it and the `census/2021` manifest is 229 kB; `from_files = TRUE` reads afresh, a new `parquet_tbl()` call on the paths replaces the entry, and `data_to_parquet()`, `upload_parquet()`, `remove_parquet()`, `write_manifest()`, `cache_parquet()` and `remove_parquet_from_cache()` call `forget_scans()` (in `R/parquet.R`) on the paths they change, which drops the `metadata` of every entry whose files or source overlap them (`scan_roots()`: globs, query strings and trailing slashes stripped, local paths also normalised, so a table rewritten in place describes the new files, added 2026-10-24 after the stale labels showed up in the blog post's iris example); `left_scan()` finds the left-hand table's entry), and `table_scans()` walks the lazy query (recursing through all list elements, so joins, semi joins and set operations alike, without depending on dbplyr's node classes) to the `lazy_base_remote_query` leaves and looks them up (tables created before `parquet_scans` was reset, as by `devtools::load_all()`, are recovered from the scan SQL by `scan_sql_paths()`, with the left-hand table's `r2parquet_source` where it matches); `parquet_sources()` returns their metadata one row per table (left-hand first, single valued entries as columns, the whole metadata as a list column), `collect_parquet()` attaches that as the `parquet_sources` attribute and adds the labels of joined columns, while the `metadata` attribute stays the left-hand table's: merging the metadata of unrelated datasets would make claims (title, licence) that don't hold for the result. `parquet_sources_attribution()` joins their `attribution` entries for captions, combining attributions that differ only in their last word (`combine_attributions()`: "Statistics Canada Product A, B"; a longer shared prefix was rejected since a shared first word like "Statistics" would merge unrelated attributions), and returns `NULL` without any so `labs(caption=)` leaves the caption out. `warn_dropped_metadata()` also names the joined tables with metadata (`joined_source_paths()`). Tests comparing with plain lists wrap it in `unclass()`. Languages (`R/metadata.R`, note at the top; the user-facing spec is the Languages section of `data_to_parquet()`): column entries hold labels and descriptions per language under suffixed keys (`label_en`, `label_fr`, `description_fr`), a plain `label` is optional, and the optional `language` entry names the language of the plain text and plain columns. Which suffixes are languages is an explicit contract, never guessed from the keys: `metadata_languages()` returns the `languages` entry (every language the dataset holds text in, written as a JSON array via `I()`, read back as a character vector) and the `language` entry, filtered by `language_code` (lowercase, 2-3 letters, optional `-subtags`), and nothing else; so `source_url`/`licence_url` are entries of their own, `title_fr` is a variant only when `fr` is declared, and a language the dataset doesn't declare leaves data and metadata as stored (`language_columns()` returns `NULL`, `resolve_language()` the metadata unchanged). `check_column_languages()` (from `metadata_strings()`, with the declared set) errors on `label_<x>`/`description_<x>` suffixes not declared, naming the `languages = c(...)` to add, so datasets written here always declare their languages. Two looser rules were dropped on 2026-10-23: a `print_languages()` that took paired two-letter top-level suffixes for languages (fragile, `source_url` looked like a language), then the label suffixes declaring languages and the language asked for counting as one (both left nothing to validate against and made `collect_parquet(language="de")` turn an unrelated `name_de` column into a translation). `resolve_language()` drops `languages` and sets `language`. Reads of the `language` entry use `[["language"]]` since `$language` partially matches a lone `languages` entry. `collect_parquet(language=)` (default the `r2parquet.language` option, `check_language()`) resolves labels through `column_text()` (`label_<asked>`, then `label`, then `label_<dataset language>`; without a language `label`, then the dataset language's, else none, so nothing is privileged) and swaps columns through `language_columns()`: columns with the suffix of one of the dataset's languages (`metadata_languages()` over all joined tables) next to a plain column, or two or more peers without one (`name_en`, `name_fr`), are translations, the one in the asked language is selected under the plain name in the query, the others dropped, a lone suffixed column or other suffixes (`rate_men`) are left alone. The metadata attached in a language is resolved by `resolve_language()` (also behind `parquet_metadata(language=)`, `parquet_sources(language=)` and `parquet_sources_attribution(language=)`): suffixed top-level entries and column labels/descriptions in the asked language replace the plain ones with the same fallback chain, the other languages' entries are dropped, `columns` is re-keyed by the collected columns via the selection, and `language` is set to the asked language, so a rewrite from the attached metadata gives a correct monolingual dataset; a dataset that doesn't declare the asked language stays as stored. `parquet_metadata()` deliberately ignores the `r2parquet.language` option so the full metadata is always one call away, the sources and attribution follow the option like `collect_parquet()`. Without a language, a dataset with text in several languages and no `language` entry resolves nothing (no plain text to fall back on), and `collect_parquet()`, `parquet_sources()` and `parquet_sources_attribution()` say so with a message once per session (`note_missing_language()`, `parquet_cache$language_noted`) naming the option and the `language` argument; `parquet_metadata()` stays quiet since it returns everything. The public census datasets are peer-only (`title_en`/`title_fr`, `languages = c("en", "fr")`, no `language`; Jens re-uploads them with `languages` after the 2026-10-23 change), so the vignettes set `options(r2parquet.language = "en")` in their setup chunk. Resolving rather than keeping all languages was chosen on 2026-10-23 because the collected columns are already monolingual. The column swap happens on the lazy table: `select_language()` (exported) selects the columns of a language through `language_columns()` with the languages from the metadata of all the table's scans, and `parquet_tbl(language=)` (default the option) chains it, so with the option set a bilingual dataset has `name`, not `name_en`/`name_fr`, and the other language is never read; `language = NULL` gives the columns as stored for chaining it by hand, also on joins. The table records the selection (result column to stored column, composed over repeated selections by `compose_selection()`) as the `r2parquet_selection` attribute and the language as `r2parquet_language`; `collect_parquet()`, `parquet_sources()` and `parquet_sources_attribution()` describe the table in that language when no `language` is passed (`table_language()` with `missing()`, so the recorded language beats the option: a table read with `language = "fr"` in an `"en"` session collects with French labels; an explicit `language`, `NULL` included, wins), `parquet_metadata()` keeps returning the metadata as stored by default, and `resolve_language(recorded=)` maps the result's columns back to the stored ones for the labels and drops the other languages' entries of selected columns (`name_fr` beside a selected `name_en`), while the collect-time swap in `collect_parquet()` stays for tables read without a language. Joined tables on the right lose the attribute, their metadata resolves from its own column entries, which are keyed by the stored columns. Selecting at read time was chosen on 2026-10-23 over selecting after collecting, which downloads the other languages' columns. An earlier version required a plain `label`, copied from the dataset's language at write time, and was dropped on 2026-10-23 to match how Canadian datasets treat English and French as peers.

**Reading (`R/parquet.R`).** `parquet_tbl()` is the one reader, for public URLs (like a public bucket's custom domain or presigned URLs), private R2 files as `r2://bucket/path` and local paths. Directories at URLs can't be globbed, so a URL ending in `/` is expanded to the file URLs its `_manifest.json` lists (`url_directory_files()`, via `url_cache_source()`), and a URL without the slash is tried as a file first and, if DuckDB fails, as a directory via the manifest, re-raising DuckDB's error when no manifest resolves; hive partition columns still come from the file paths. Failed reads get translated by `read_error()`, which parses DuckDB.s message (the failed file or glob, the HTTP status, an S3 error code line) into an `r2parquet_not_found` or `r2parquet_access_denied` condition (`r2parquet_error()` in `R/r2.R`) naming the path as resolved, passing other errors on unchanged; local paths are told apart as missing or an empty directory only after the read failed, so successful reads cost nothing extra. `access_hint()` appends what a 401/403 depends on (R2 or AWS credentials, the expiry of presigned URLs from `X-Amz-Date`/`X-Amz-Expires`, public access) to that; the request helpers in `R/r2.R`, `R/cache.R` and `R/s3.R` raise their "failed with status" errors through `stop_for_status()`, which gives the same classes for 401/403 and 404 and plain errors otherwise, so failures of `cache_parquet()`, `upload_parquet()` and the listings can be caught like read failures (helpers that treat a 404 as absence, like `r2_object_exists()`, check for it first). Connection failures become `r2parquet_network_error` (`network_error()`): `with_network()` wraps every httr request (`r2_request()`, `http_get()`/`http_probe()`/`http_download()`, `cloudflare_api()`) and catches `curl_error`, `read_error()` recognises DuckDB's `IO Error: <reason> error for HTTP <verb> to '<url>'`, `load_extension()` a failed first `INSTALL`, and `collect_parquet()` translates errors at query time through `read_error()` too; code that falls back on failed lookups (`url_parquet_files()` for `list_parquet()`) lets network errors through. Errors rather than warnings returning `NULL` were chosen for CRAN's "fail gracefully" policy: informative, classed errors that callers can catch, with `R CMD check` kept off the network instead. The resolved files are stored as the `r2parquet_paths` attribute (local copies for cached paths) and the paths as given as `r2parquet_source`, which `list_parquet()` and `remove_parquet()` use for a lazy table (`table_source()`), so a table read from the cache lists and removes the remote files; `is_bucket_path()`, `is_url()` and `is_remote()` (bucket or https) are the three path tests. It returns a lazy `dbplyr` table on a single session-cached in-memory DuckDB connection, exported as `parquet_connection()`, so all tables can be joined; `con=` puts the table on a user's own connection instead. Arrow and polars readers (an `engine` argument) existed before the first release and were dropped: arrow reads GeoParquet 2.0 geometry as plain binary without crs, polars (1.16) rejects the native GEOMETRY type outright, and neither is on the DuckDB connection, so `st_filter()`/`collect_parquet()` didn't apply; polars also isn't on CRAN. Adding an `engine` argument back later is backward compatible. For `r2://` paths `parquet_tbl()` runs `CREATE OR REPLACE SECRET` on every call, so credentials are only needed once R2 is read and changed credentials get picked up; the secret sets `REGION 'auto'` explicitly, otherwise DuckDB takes the region from `AWS_DEFAULT_REGION` and R2 rejects it. Internal short-lived connections (`parquet_footers()`) are opened with `duckdb_connect_quietly()`, which suppresses duckdb's RStudio Connections pane registration on open and close (`duckdb.enable_rstudio_connection_pane`): every in-memory connection registers as "DuckDB" at ":memory:" and closing one removes the first entry with that host, so transient connections left the pane calling closed ones ("Invalid connection" from `rapi_prepare`, October 2026); only the session connection shows up in the pane. The session connection (`parquet_connection()`, not `con=`, dbplyr compares connections by identity so a wrapped copy of a user's connection could not be joined with their own tables) is wrapped as the S4 class `r2parquet_connection` (contains duckdb's connection class, so all its methods apply; lazy tables are therefore `tbl_r2parquet_connection`, not `tbl_duckdb_connection`, `local_data_to_parquet()` checks the connection class instead) whose dbplyr translation (`sql_translation.r2parquet_connection`, registered for `dbplyr::sql_translation`) renders whole-number doubles in comparisons and `%in%`/`between` as integers via `integer_literal()`, with a message once per session: dbplyr renders `x == 1` as `x = 1.0`, and DuckDB 1.5.6 casts an INTEGER column to match, inside the scan filter, so no row groups get pruned (540 range requests instead of 46 on the public profile dataset, which tripped the Cloudflare rate limit). Arithmetic is left alone so integer columns don't overflow, dates (doubles with a class) pass through. Hive partition columns are read as strings (`hive_types_autocast = false`, so `PRUID=01` and `PRUID=10` get the same type), and a number against a VARCHAR column gets the column cast above the scan, reading every partition, so numbers in `==`, `!=` and `%in%` against a partition column are rendered as string literals (`partition_literal()`, its own once-per-session message), which DuckDB prunes partitions on; order comparisons are left alone since strings compare lexicographically, and DuckDB refuses `PRUID > 10` on a VARCHAR column with a binder error asking for an explicit cast, which beats a silently wrong `PRUID > '10'`. The translation only sees column names, so `parquet_tbl()` records the partition columns of every table it creates in the `parquet_partitions` environment (and as the `r2parquet_partitions` attribute), found as the columns beyond those a `DESCRIBE` of the scan without hive partitioning shows (the same `DESCRIBE` that detects GEOMETRY columns); a same-named numeric column elsewhere is unaffected because DuckDB casts a string literal against a numeric column on the literal side. The R duckdb package sets `autoinstall_known_extensions = false`, so extensions have to be `INSTALL`ed explicitly even though they autoload afterwards: `httpfs` gets installed for URLs, and `spatial` only when `DESCRIBE` (footer only) shows a GEOMETRY column, since spatial functions like `ST_MakeEnvelope`/`&&` do not autoload; `load_extension()` does the `INSTALL`+`LOAD` pair everywhere. GEOMETRY columns and `ST_CRS` work without `spatial` (the crs then comes back as PROJJSON instead of `EPSG:n`).

**Local cache and manifests (`R/cache.R`).** `cache_parquet()` mirrors remote datasets into a cache directory, `r2://bucket/path` as `r2/<account id>/bucket/path` (bucket names are only unique per account) and URLs as `<scheme>/<host>/<path>` without the query string, and `parquet_tbl(cache=)` reads the local copy, so everything downstream sees plain local paths. The three resolvers `cache_lookup()`, `cache_parquet()` and `cache_offline()` share `resolve_remote()`, which maps the remote paths of a vector and passes local ones through. `cache = NULL` (the default) goes through `cache_lookup()`: a path without a copy in the cache (`cached_copy()`) is read remotely without any request, a copy is checked against the remote (`cache_current()`, every remote file current by etag and size and no extra local parquet files in a directory, against the nearest manifest above that covers the path via `covering_manifest()`, since a file or partition of a cached directory is listed in that directory's manifest) and used if current, otherwise the remote path is read with a warning and the copy is left alone. `sync_cache()` keeps that one-manifest picture consistent: a file, or a directory below a directory whose manifest is complete (`directory=TRUE`), is recorded in the covering manifest instead of getting one of its own (a directory below a manifest that only lists cached single files keeps its own, so its completeness stays known to `cached_copy()`), a directory sync deletes the manifests below it, and every sync patches the entries below the synced path in all ancestor manifests (`patch_ancestor_manifests()`), with entries kept sorted by path (`sorted_files()`, byte order like listings, also used by `r2_update_manifest()` and `cache_contents()`). `cache_ancestors()` is the one walk from a path up to the top-level directories of the cache, with the path relative to each, used by `covering_manifest()`, `cached_copy()`, `patch_ancestor_manifests()` and `prune_manifests()`; `is_remote()` is the `r2://`-or-https test the cache functions share. The result of that check is memoised per session in the `cache_checks` environment, keyed by the local path (so it is per cache directory and account), and only `clear_cache_checks()`, `cache_parquet()` (sets it to current) and `remove_parquet_from_cache()` (`forget_checks()`, which also drops the entries above and below the path) change it; a failed check is not memoised. `cache = TRUE` goes through `cache_parquet()` and updates the copy on every call; `cache = "offline"` (`cache_offline()`) returns the copy without any request, stale or not, and errors without one, for offline work and for comparing the copy with the remote (`cache = FALSE`). Freshness is per file by etag: for `r2://` from the listing (`r2_list_objects()` parses `ETag`, which R2 sets to the content MD5 for single-PUT uploads, so downloads get verified against it when it looks like an MD5), for file URLs from a `HEAD` request, falling back to a GET of the first byte on 403/405 (`http_probe()`, `Range: bytes=0-0`; a `HEAD` gets 403 on presigned URLs since they are signed for GET, the 206 response carries the etag and the total size in `Content-Range`), and for directory URLs from a `_manifest.json` next to the data, since directories can't be listed over https. One manifest per directory, JSON with `directory` (whether it lists everything below, as R2 manifests and cached directories do, versus only cached single files), `metadata` (the footer metadata shared by all parquet files below, `columns` included) and `files` with path, size, etag, modified and, where a file's footer differs from the shared metadata, its own `metadata` (`columns` included, so rewrites that carry entries over from the existing manifest lose nothing); the format is a public contract documented in `?write_manifest`, `manifest_json()`/`parse_manifest()` in `R/cache.R` write and read it (`parse_manifest()` merges the shared entries back into each file and flags `has_metadata` so manifests from before the metadata, which have no `metadata` key, don't pass off empty entries as known). The `directory` flag is what the offline fallback (`cached_copy()`) checks so a directory holding a cached single file isn't mistaken for a cached dataset. Local manifests must stay sidecars, the etag is a hash of the file. Keys become URL paths through `url_path_encode()` (`URLencode` plus `#` and `?`), used for file URLs from manifests, `cache_remote_path()` and the Cloudflare purge. On R2, `r2_upload()` (behind `upload_parquet()` and `r2_data_to_parquet()`) creates the manifest for directory uploads via `r2_update_manifest(create=TRUE)`, `remove_parquet()` deletes manifests below removed directories, `write_manifest()` adds them to existing directories, and all of them purge the manifest from the Cloudflare cache along with the data. `r2_update_manifest()` GETs the existing manifest first (`r2_get_manifest()`, which returns the response etag as an attribute and warns and treats an unparseable manifest as missing metadata, see `manifest_response()` above) and either *rebuilds* it from a listing (`r2_manifest_from_listing()`: with `create`, or when the existing manifest predates the metadata; it carries a file's metadata over when its etag is unchanged and reads the footers of everything else from R2, one range request per file, which is the cost `write_manifest()` documents) or *patches* it from what it records (removed and uploaded paths dropped, the `uploaded` entries added, no listing, no footer reads), then PUTs it conditionally: `If-None-Match: *` when none existed, `If-Match: "<etag>"` otherwise, a 412 starts the attempt over, three attempts and then an error; a manifest left without files gets deleted. The entries of uploaded files (`r2_upload_entries()`: local size, MD5 as the etag R2 will assign, upload time, metadata from the local footers via `parquet_footers()`, a fresh DuckDB connection per call so DuckDB's footer cache can't serve stale metadata, with the R2 secret for `r2://` paths) are built before any PUT, and the etag is replaced with the one the PUT response returns. Since a manifest lists every parquet file below its directory (the one a partitioned `data_to_parquet()` writes sits at the dataset root), uploads and removals of parquet files also patch the existing manifests of all directories above the changed keys (`r2_ancestors()`) and directory uploads those below the destination (found in the listing), through `r2_update_manifests()`, which catches failures per manifest and turns them into one warning naming the manifests that are out of date (the data is already changed at that point, `write_manifest()` repairs them); without `create` a missing manifest is left alone, so ancestors without one, in particular the bucket root, don't get listed, and removing or uploading a non-parquet file touches no manifest. Patches trust the manifest, so drift from changes made with other tools persists until a directory upload or `write_manifest()` rebuilds it. `r2_upload(stale=)` takes a function of the listing and the uploaded keys returning the keys to delete before the upload: `r2_stale_mirror()` for `upload_parquet(remove_stale=TRUE)`, the hive partition rule for `r2_data_to_parquet()`; the listing is taken once, of the destination directory for directory uploads and of the single file otherwise. Directory uploads to the bucket root are refused (the root manifest would list the whole bucket and `remove_stale` would empty it), single files may go to the root and `write_manifest("r2://bucket")` is the explicit way to get a root manifest. Mocked tests that reach this need `r2_get_manifest()` mocked or a `GET` branch for `_manifest.json` in their `r2_request()` mock (`manifest_bucket()` in `helper.R` serves manifests from a `bodies` list and records PUTs), otherwise they send real requests with whatever credentials `~/.Renviron` holds; running the offline tests with `R_ENVIRON_USER=/dev/null` catches that. `helper.R` also unsets the `r2parquet.language` option, which the maintainer's `.Rprofile` sets to `"en"`, since the tests assert what collecting without a language gives. Downloads go through `r2_get_object()` (`r2_request(config=httr::write_disk())`, streaming, unlike uploads) to a `.download` temp file that is renamed into place. `list_parquet_cache()` and `remove_parquet_from_cache()` work on the configured cache directory like everything else: `cache_contents()` reads every local manifest and maps the local paths back to remote ones with `cache_remote_path()`, the reverse of `cache_location()` (`cache_directory()` returns forward slashes so these paths compare with what `dirname()`/`dir()` return on Windows; tests use `local_cache_dir()` from `helper.R` for the same reason), and `remove_parquet_from_cache()` deletes the copy and then `prune_manifests()` walks up to the cache directory dropping the entries from ancestor manifests, flipping a directory manifest to `directory=FALSE` when it loses entries (so the offline fallback no longer treats it as complete) and removing emptied directories. `list_parquet()` gets its `cache` column from `cache_status()`, comparing the remote etag with the one the manifest recorded (`NA` when either is unknown, e.g. local paths); for URLs `list_parquet()` lists through `url_cache_source()` as well, so files get size and etag from their headers and directories are listed from their manifest, falling back to a bare row with `NA`s.

**Why not duckdbfs.** `duckdbfs` covers similar reading ground, but the CRAN version lacks crs reading for GeoParquet and the package does not seem actively maintained, so the thin DuckDB readers here are kept on purpose.

**Dependencies.** Everything is called with explicit `pkg::fn()` qualification, there are no function imports; the one namespace import is `importClassesFrom(duckdb, duckdb_connection)`, which the S4 class `r2parquet_connection` needs at install time (`methods::className()` does not resolve there). `duckdb`, `DBI`, `dbplyr`, `dplyr`, `sf`, `httr`, `digest`, `jsonlite` and `mime` (already pulled in by httr, used for upload content types) are the hard dependencies, there are no optional ones (`Suggests` only holds test and vignette tooling).

## Conventions

- Two-space indentation, `=` and `<-` both used for assignment, compact spacing (`function(d)d`). Match the surrounding file.
- Every exported function has a roxygen block with `@param` for each argument, `@return`, and `@export`.
- Examples that need the network (including DuckDB extension downloads) go in `\donttest{}` with an `if (requireNamespace("curl", quietly = TRUE) && curl::has_internet())` guard, and read little: `--as-cran` runs them.
- Regexes with `perl = TRUE` must not use lookbehinds of varying length (`(?<=error (on|reading) )`): PCRE2 before 10.43, as on Ubuntu CI, rejects them while macOS accepts them. Use a capture group with `regexec()` instead.
