# Code review, 2026-10-13

Review of the package at commit e0396ce for problems, pitfalls and consolidation. The full test suite
passed at the time, including the integration test. Items marked *fixed* were addressed right after the
review, the rest is open.

## Bugs

- **`collect_parquet()` failed on NULL geometries** (*fixed*). A table whose geometry column holds NULLs,
  e.g. after a left join or from source data with missing geometry, errored in `sf::st_as_sfc()` with
  `vapply(x, is.raw, TRUE) are not all TRUE` (`R/geoparquet.R`, the WKB conversion in `collect_parquet()`).
  Empty geometries were fine, NULLs were not. NULLs now become empty geometries.
- **The `remove_parquet` test in `test-delete.R` made live requests** (*fixed*). It mocked
  `r2_object_exists()`, but removals reach the manifests through a GET in `r2_get_manifest()`, not a HEAD, so
  the test sent real GETs for `bucket/_manifest.json` and `other/_manifest.json` with the credentials from
  `~/.Renviron` and only passed because they got 404s. With `R_ENVIRON_USER=/dev/null` it failed with
  "Missing environment variables". The mock is now `r2_get_manifest()`. Running the offline tests with
  `R_ENVIRON_USER=/dev/null` is a cheap way to catch this class of leak.
- **Writing into a missing local directory fails with a raw DuckDB IO error.** Both
  `data_to_parquet(df, "new/f.parquet")` and a partitioned write into a missing parent fail at the `COPY` in
  `local_data_to_parquet()`. A `dir.create(dirname(path), recursive = TRUE)` before the `COPY` would fix it.
- **Metadata strings that look like JSON come back parsed.** `metadata = list(notes = "[1]")` reads back as
  the integer 1, since `parse_metadata_value()` (`R/metadata.R`) parses any value starting with `[` or `{`.
  Unlikely in practice but a silent type change, and the manifest format inherits it. Either document it or
  only parse entries known to be structured.

## Pitfalls

- **Directory URLs can't be read without caching.** `parquet_tbl("https://host/dataset/")` fails with a
  DuckDB 404 even when a `_manifest.json` sits next to the files. The manifest exists to solve exactly this,
  and `url_cache_source()` already turns it into file URLs. Biggest functional gap for public readers of
  partitioned datasets, see possibilities.
- **Range-ignoring servers trigger full downloads.** `http_probe()` (`R/cache.R`) buffers the whole
  response, so a host that ignores `Range` downloads the file just to read its etag. R2 honours it, other
  hosts may not.
- **Manifests at the bucket root are expensive.** Every upload and removal GETs the manifest of every
  ancestor up to the root (`r2_upload()`, `remove_parquet()`). After `write_manifest("r2://bucket")`, each
  single-file change lists and rewrites the entire bucket. Removing a non-parquet file also walks the
  ancestors although no manifest content changes.
- **Nested cache manifests can go stale.** Caching a single file inside a partition of an already cached
  directory writes a second manifest in the partition directory (`sync_cache()` writes into
  `manifest_directory()`). A later sync of the directory rewrites only the top manifest, and
  `covering_manifest()` prefers the nearest one, so the file reads as stale and gets downloaded again.
- **Two definitions of "URL".** `duckdb_parquet_paths()` and `list_parquet.character()` use
  `^[a-z0-9]+://`, the cache code uses `^https?://`. An `s3://` path counts as a URL for reading and as local
  for caching. Harmless today.
- **Key encoding edge cases.** `r2_purge_cache()` encodes keys with `URLencode` defaults, so `#`, `?` or
  `+` in a key yield a wrong purge URL, and keys with `*`, `?` or `[` would be read as globs by DuckDB in
  `parquet_footers()`.
- **CLAUDE.md drift.** It said `r2_update_manifest()` sends a HEAD and that mocked tests need
  `r2_object_exists()` mocked; both referred to the GET in `r2_get_manifest()` (*fixed*). Its list of offline
  test files omits `test-metadata.R`, `test-parquet.R` and `test-credentials.R`.

## Consolidation

- **Metadata across files is computed three ways.** `duckdb_parquet_metadata()` warns on conflicts and
  takes the first file, `common_metadata()` computes the shared entries, `parquet_footers()` reads per file.
  One per-file reader plus `common_metadata()` would serve all three and make `parquet_metadata()` on a
  directory consistent with what the manifest records.
- **`r2_parquet_files()` duplicates `r2_cache_source()`.** Same listing, same file-or-directory decision.
  `list_parquet.character()` already goes through `url_cache_source()` for URLs, so it could use
  `cache_source()` for both remote kinds. `manifest_files()` and `parquet_files()` are two constructors for
  the same four columns.
- **Three walk-up loops.** `covering_manifest()`, `cached_copy()` and `prune_manifests()` each climb
  `dirname()` to the cache directory with the same `startsWith(directory, paste0(cache_dir, "/"))` guard.
- **Small repeated idioms.** `INSTALL x; LOAD x` in six places; the `object_size` formatting in
  `sync_cache()` and `r2_data_to_parquet()` although `format_size()` exists; the remote-path test
  (`startsWith(p, "r2://") || grepl("^https?://", p)`) about six times; the trailing-slash strip
  `sub("/+$", "", ...)` eleven times; the stale-file removal with its message in both `r2_upload()` and
  `r2_data_to_parquet()`; `local_data_to_parquet()` loads spatial twice for sf. Letting `r2_split_path()`
  strip slashes and return a directory flag would remove most of the strips. The credentials paragraph in the
  roxygen blocks is repeated five times and could be one `@inheritSection`.
- **`r2_update_manifest()` lists twice and checks twice.** `write_manifest()` lists the directory and the
  function lists it again; `r2_upload(remove_stale = TRUE)` lists three times. After the GET of the existing
  manifest, the `exists <- key %in% objects$key` check is redundant. Passing `objects` in would save a
  listing per call.

## Possibilities

- **Resolve directory URLs through the manifest in `parquet_tbl()`.** Read `_manifest.json`, pass the file
  URLs as a list to `read_parquet`; hive partitioning still works since DuckDB derives it from the paths.
  Reuses `url_cache_source()`.
- **Let `parquet_metadata()` read manifests for directories.** The `has_metadata` flag already says when a
  manifest can be trusted; it saves one range request per file on R2 and makes directory URLs work at all.
- **Skip ancestor manifest updates when no parquet key changed**, e.g. when removing a JSON index.
- **Streaming uploads.** `r2_put_object()` reads the file into memory. `curl` is already a dependency
  through httr, so a `curl` upload with a precomputed SHA-256 would lift the RAM limit without httr's
  connection leak, and multipart would lift the 5 GB limit.
